## 一、写作口径与当前正式实现边界

本文只整理黄色道路边界识别、红白反坦克雷圆片识别、相机标定、米制鸟瞰变换、视觉结果进入导航世界模型以及视觉计算资源优化等内容。

当前正式视觉导航链为：

```text
RGB 图像
→ 左侧黄色边界检测
→ 红白反坦克雷圆片检测
→ 去畸变与米制地面投影
→ 多帧跟踪确认
→ 黄线走廊与圆片冻结到 odom
→ costmap 栅格障碍 + TEB 紧凑语义障碍
→ GlobalPlanner + TEB
```

撰写最终报告时需要特别注意以下事实：

1. 当前反坦克雷视觉检测不使用 YOLO，也不使用深度图，而是采用针对固定颜色和几何结构设计的轻量传统视觉算法。
2. 当前正式运行只检测左侧黄色边界，右侧边界根据固定的 `0.91 m` 黄线中心距在世界坐标中生成。
3. 当前正式局部规划器已经是 TEB，不是报告旧稿中仍在描述的 DWA。视觉章节应按当前 GlobalPlanner + TEB 接口叙述。
4. 视觉在完成黄线走廊和两枚圆片建模后进入 `LOCKED` 状态，不再重复执行重型图像处理。
5. 当前视觉世界模型冻结后不会主动修正车辆后续产生的绝对 x/y 漂移。低频视觉地标位置校正目前只有设计文档，尚未作为正式实现使用。
6. 历史 40 cm 间距测试属于识别与几何精度压力测试，不是正式比赛的控制状态或固定门宽逻辑。

# 二、可用于摘要的视觉避障段落

视觉避障模块针对赛场内二维激光雷达不易稳定探测的低矮红白反坦克雷圆片，构建了基于 RGB 图像的轻量化环境感知链。系统首先通过连续颜色置信度、法向截面采样、动态规划和加权直线拟合提取黄色道路边界，再利用红色椭圆候选、环形扇区覆盖、白色中心中性度及同心性约束识别反坦克雷圆片。经相机去畸变和米制鸟瞰投影后，检测结果被转换至机器人地面坐标，并结合时间同步的 TF 固定到 odom 世界坐标，持续生成导航代价地图障碍和紧凑几何障碍模型。针对车载 N95 平台算力有限的问题，系统设计了 ACQUIRE—LOCKED 两阶段感知模式：完成走廊及两枚圆片建模后，视觉节点停止重型图像处理，而下游仍利用冻结世界模型持续规划。固定场景测试中，视觉 CPU 占用由 ACQUIRE 阶段约 283% 降至 LOCKED 阶段约 8.9%，在保持导航障碍持续发布的同时显著释放了规划计算资源。

# 三、1.2.3.4 视觉避障——研究与技术背景初稿

视觉避障是移动机器人环境感知的重要组成部分，其目标是从相机图像中提取道路可通行区域、边界及障碍物信息，并将其转换为规划器能够使用的空间约束。传统视觉避障方法通常利用颜色、纹理、边缘、轮廓和几何结构等人工特征，具有计算过程清晰、可解释性强、对训练数据依赖较小等特点；深度学习方法则通过卷积神经网络或端到端模型学习场景特征，在复杂环境中具有较强的特征表达能力，但通常需要较大的数据集和更高的计算资源。

道路边界检测领域早期广泛采用颜色分割、边缘检测、霍夫变换和多项式拟合等方法。为减弱透视成像对距离和形状判断的影响，逆透视映射（Inverse Perspective Mapping，IPM）和鸟瞰变换（Bird's-Eye View，BEV）被用于将地面区域转换到近似俯视坐标，使车道边界的方向、间距和障碍物位置能够以统一的地面尺度表达。Bertozzi 和 Broggi 的 GOLD 系统是采用立体视觉与逆透视映射完成车道和障碍检测的代表性研究之一。

近年来，SCNN、Ultra-Fast-Lane-Detection 等深度学习方法通过空间信息传播或行锚分类提高了车道线检测能力，在复杂道路和遮挡场景中表现出较强的鲁棒性。但竞赛中的黄色边界具有颜色明确、区域固定、结构简单等特点，车载 N95 计算平台还需要同时承担导航规划和其他视觉任务，因此本项目没有复现上述深度网络，而是根据赛场先验设计了轻量的连续颜色置信度与结构约束算法。

对于反坦克雷圆片，其高度较低，二维激光雷达扫描平面可能高于目标表面，难以获得稳定回波；同时圆片具有明显的红色外环、白色中心和近似圆形的固定结构，适合采用 RGB 颜色与几何联合约束进行检测。与仅采用红色阈值分割相比，红环覆盖、白心亮度与低饱和度、Lab 中性色、红白同心性以及多帧确认等约束能够显著降低红色背景物和局部高光造成的误检。受透视成像影响，地面圆片在图像中通常呈椭圆形，因此本项目对候选轮廓进行椭圆拟合，而不是强制将其视为图像平面上的标准圆。

相机标定是视觉几何测量的基础。项目使用平面棋盘格完成相机内参和畸变系数估计，其基本方法属于张正友平面标定方法体系；在地面投影阶段，根据相机与地面的相对安装关系建立单应变换，将图像像素映射为机器人坐标系下的米制地面坐标。相机内参反映镜头与成像器件特性，而地面单应关系取决于相机安装姿态，两者需要区分：当相机支架被碰动但镜头焦距、分辨率不变时，内参通常仍可保留，地面外参与 Homography 则必须重新标定。

# 四、2.2.3 反坦克雷检测与规避——总体设计思路初稿

赛场反坦克雷为随机摆放在黄色边界道路内的低矮红白圆片。由于圆片高度较低，二维激光雷达的固定扫描平面难以保证稳定命中目标，本系统使用安装在车体前部的 RGB 相机完成道路边界和圆片感知。视觉模块不直接输出运动速度，而只负责建立可供导航系统使用的环境模型，从而将感知与运动控制解耦。

系统首先对 RGB 图像进行相机去畸变，在限定的地面感兴趣区域内计算黄色连续颜色置信度。针对黄色边界在透视图像中方向和宽度随距离变化的问题，算法沿边界法向设置多条截面，在每个截面中提取候选响应，再通过动态规划寻找跨截面连续的最优边界序列，最后使用加权总最小二乘方法拟合边界直线。正式比赛中只检测较稳定的左侧黄线，并根据场地已知的 `0.91 m` 黄线中心距生成右侧边界，从而构成完整的道路走廊。

反坦克雷识别采用颜色与几何联合判定。算法先从红色区域中提取轮廓并拟合椭圆，再检查椭圆环带的红色覆盖程度、20 个角向扇区的连续覆盖、中心区域的亮度与低饱和度、Lab 中性色、中心排红以及红白结构同心性。通过这些条件筛除普通红色物体、黄色边界、高光和不完整色块。检测结果经过米制地面投影后，在 BEV 坐标中进行多帧关联和确认，连续满足条件的目标才被写入正式世界模型。

确认后的黄线走廊和圆片中心依据图像时间戳对应的 TF 转换到 odom 坐标系，并在单次比赛任务中冻结。黄线由持续发布的走廊点云写入局部和全局代价地图，圆片由虚拟 LaserScan 写入代价地图；同时，TEB 局部规划器接收两条线障碍和两枚圆形障碍组成的紧凑语义模型。GlobalPlanner 使用完整代价地图生成全局路径，TEB 根据少量几何障碍优化全向底盘轨迹，避免将上千个占用栅格逐一作为独立优化障碍。

为降低比赛运行阶段的计算负载，视觉节点采用 ACQUIRE—LOCKED 两阶段模式。ACQUIRE 阶段运行完整黄线和圆片识别；当走廊、两枚圆片、冻结状态和代价地图写入状态持续稳定后，节点锁存为 LOCKED，并在图像回调最前端跳过后续图像转换和识别运算。导航系统继续使用冻结的世界模型，因此无需持续重复识别静态赛场目标。

# 五、2.3.2 视觉避障系统设计——全面初稿

## 2.3.2.1 任务特点与系统总体架构

反坦克雷视觉避障区域同时包含道路边界约束和随机障碍约束。机器人不仅需要避开两枚圆片，还必须避免矩形车体越过黄色道路边界。视觉系统需要完成以下任务：

1. 从相机图像中提取道路方向和左侧黄色边界；
2. 根据固定道路几何生成右侧边界，形成米制可通行走廊；
3. 识别两枚具有红色外环和白色中心的低矮圆片；
4. 将像素检测转换成机器人地面坐标和 odom 世界坐标；
5. 对检测结果进行多帧确认，防止单帧误检进入导航地图；
6. 向局部、全局代价地图和 TEB 提供持续、稳定的障碍信息；
7. 在完成静态世界建模后停止重复计算，为局部规划器释放 CPU。

当前系统的模块关系如下：

```text
usb_cam RGB 图像
        ↓
yellow_track_avoidance 视觉节点
        ├─ 左黄线检测与质量评价
        ├─ 红白圆片检测
        ├─ 米制地面投影
        └─ 多帧跟踪与确认
        ↓
competition_corridor_map
        ├─ 锁定左边界
        ├─ 推算右边界
        └─ 发布 corridor_cloud
        ↓
disc_laserscan_bridge
        ├─ 圆片转换至 odom
        ├─ 冻结确认位置
        └─ 发布 disc_scan
        ↓
local/global costmap
        +
TEB compact obstacles（2 条线 + 2 个圆）
        ↓
GlobalPlanner + TEB
```

视觉节点正式配置中 `enable_planning=false`、`enable_motion=false`。视觉调试速度输出被隔离到 `/yellow_track_avoidance/perception_cmd_vel`，不直接发布底盘使用的 `/cmd_vel`，因此不存在视觉控制器与 move_base 争夺车辆控制权的问题。

## 2.3.2.3 感兴趣区域设置

系统只在图像下半部分及道路可能出现的区域运行重型检测，以减少无关背景干扰。当前通用检测区域由归一化多边形和下半幅范围共同限制，黄色边界还使用偏左的专用多边形区域，使算法重点搜索左侧黄线。

通用归一化区域近似为：

```text
(0.00, 1.00)
(0.10, 0.50)
(1.00, 0.50)
(1.00, 1.00)
```

黄色边界区域近似为：

```text
(0.00, 1.00)
(0.00, 0.65)
(0.10, 0.50)
(0.55, 0.50)
(0.50, 1.00)
```

当前 `use_bev_polygon_for_detection=false`，因此检测 ROI 采用上述图像归一化多边形；配置文件中保留的部分 BEV 源点用于透视变换，不应误写成当前检测 ROI。

## 2.3.2.4 黄色道路边界检测算法

### （1）连续颜色置信度

简单的固定 HSV 二值阈值容易受到曝光变化、黄色漆面反光、绿色地面和白色高光影响。当前正式实现采用 `yellow_confidence_v2` 计算连续黄色置信度，而不是只给出“黄/非黄”的二值判断。

主要颜色证据包括：

1. **YCrCb 对手色差。** 定义

   \[
   D=Cr-Cb
   \]

   黄色区域通常具有较高的红色差分量和较低的蓝色差分量，因此 `Cr-Cb` 可作为主要黄色证据。当前通过中心约为 10、尺度约为 6 的平滑 Sigmoid 将其转换为连续置信度。

2. **HSV 色相与饱和度辅助。** 黄色 Hue 的主要响应范围设置在约 10～42，峰值约为 25，并通过饱和度门控抑制灰白区域。HSV 在最终置信度中作为约 0.2 权重的辅助奖励，而不是唯一判据。

3. **绿色背景惩罚。** 使用归一化绿色超量

   \[
   E_g=\frac{\max(G-R,0)}{R+G+B+1}
   \]

   识别绿色地面倾向，并施加约 0.7 权重的惩罚，减少草绿色或绿色地垫被识别为黄色的情况。

4. **白色高光抑制。** 对高亮度且色度接近中性的像素进行惩罚，避免灯光反射和白色区域在低饱和状态下进入黄色候选。当前亮度中心约 245，低色度中心约 10，高光惩罚权重约 0.9。

当前配置仍保留较早期的 HSV、Lab-b、Cb 和行参考自适应颜色评分模块，但由于正式配置启用了 `yellow_confidence_v2`，该旧评分路径不是当前主要生效算法。最终报告不应将 Lab-b 写成当前正式 v2 的核心输入，可在方案演进中说明其曾作为旧版候选方法。

### （2）法向截面采样

黄色边界在透视图中通常倾斜，远处较窄、近处较宽。若使用固定水平扫描线，扫描方向可能与边界不垂直，容易把长条反光或背景纹理误认为边界。系统根据黄线的名义方向建立 28 条法向截面，使每条截面近似垂直穿过黄线。

在每条截面上，算法以 2 px 步长采样黄色置信度、局部增量、脊线响应和内侧边缘响应。搜索走廊随距离变化，远端半宽约 25 px，近端半宽约 60 px，以适应透视缩放。相邻截面候选位置最大变化限制约为 8 px。

每个候选的综合得分由下列信息组成：

```text
基础颜色置信度        0.35
局部颜色增量          0.30
黄线脊线结构          0.25
道路内侧边缘          0.10
```

其中道路参考点向黄线内侧偏移 8、12、16 px，脊线响应在 3、5、8、11 px 等尺度上计算，用于区分真正的连续条带和孤立色块。

### （3）动态规划连续路径

单个截面可能因圆片遮挡、反光或局部磨损缺少可靠候选，因此系统不对各截面独立取最大值，而是使用动态规划在全部截面候选中寻找总得分最高且空间连续的路径。目标函数同时考虑：

- 当前截面的候选响应；
- 相邻截面位置变化的平滑代价；
- 偏离名义黄线位置的代价；
- 最大允许偏移变化。

当前动态规划平滑权重约为 0.12，位置先验权重约为 0.08。该方法允许少量截面暂时缺失，同时抑制候选点在不同色块之间跳跃。

### （4）加权直线拟合与质量评价

动态规划得到的支持点根据候选置信度进行加权，并通过总最小二乘/PCA 形式拟合直线。与普通纵向最小二乘相比，总最小二乘同时考虑横纵坐标误差，更适合任意方向的图像直线。

当前边界有效性门限包括：

| 指标 | 当前门限或配置 |
|---|---:|
| 截面数 | 28 |
| 最少有效截面 | 10 |
| 最低支持率 | 0.32 |
| 最低覆盖率 | 0.50 |
| 中位颜色置信度 | ≥0.40 |
| 中位显著度 | ≥3.0 |
| 拟合 RMS | ≤5 px |
| 最大连续缺失 | ≤6 个截面 |
| 最低整线质量 | 0.50 |

整线质量由支持率、置信度、显著度、拟合误差、覆盖率和几何一致性加权构成：

\[
Q=0.25Q_s+0.20Q_c+0.15Q_p+0.15Q_f+0.15Q_v+0.10Q_g
\]

式中，\(Q_s\) 为支持率质量，\(Q_c\) 为颜色置信度质量，\(Q_p\) 为显著度质量，\(Q_f\) 为拟合质量，\(Q_v\) 为覆盖率质量，\(Q_g\) 为方向和位置等几何质量。

正式实现只输出当前观测行范围内的有效线段，不再使用历史版本中向图像上下方盲目延长检测直线的做法，从而减少无观测区域的几何误差。

### （5）单边检测与道路走廊生成

当前正式模式为 `left_only`，只检测左侧黄线。左线通过连续 5 帧的方向和横向位置一致性检查后被锁定到 odom 坐标系。锁定条件还包括边界质量不低于 0.40、航向离散不超过约 2°、横向离散不超过约 0.025 m。

右侧黄线根据道路固定几何生成。设锁定左线方向单位向量为 \(\mathbf t\)，指向道路内部的法向单位向量为 \(\mathbf n\)，则右侧黄线中心线可写为：

\[
\mathbf p_R=\mathbf p_L+0.91\mathbf n
\]

其中 `0.91 m` 是当前视觉避障赛段采用的黄线中心距配置值。黄色线宽按 `0.03 m` 建模；向 TEB 发布内边缘时，两侧中心线各向道路内部移动半个线宽，即 `0.015 m`。

走廊一旦锁定，后续地图发布不再依赖实时黄线检测。需要强调，右边界是根据已知宽度推算得到的，并非相机在正式模式中独立检测所得，因此不能使用“左右黄线间距始终检测为 0.91 m”作为 BEV 独立精度证据。

## 2.3.2.5 红白反坦克雷圆片检测算法

### （1）红色候选生成

圆片外环为红色。算法在 HSV 空间中使用跨越色相首尾的两段红色范围：

```text
H = 0～15
或
H = 155～179
S ≥ 5
V ≥ 60
```

红色掩膜经过小尺度闭运算和横向结构修复后提取轮廓。当前候选轮廓面积范围为 30～120000 px²，最低圆度约 0.03，允许的最小长短轴比约 0.08，最小短轴约 2.5 px，最大长轴约 180 px。门限设置相对宽松，是因为地面圆片在透视图中会形成明显椭圆，且远近尺度差异较大。

### （2）椭圆拟合

对于包含至少 5 个轮廓点的候选，系统使用 OpenCV `fitEllipse` 获得中心、长短轴和方向；点数不足时使用最小外接圆作为降级候选。选择椭圆而不是强制圆形的原因是：地面圆片经透视投影后通常表现为椭圆，若仅使用图像圆度，会错误拒绝远处或视角较斜的真实圆片。

### （3）红环 20 扇区覆盖

仅检查红色像素总量可能把一块普通红色区域误认为圆片。系统在拟合椭圆的归一化坐标中定义红环区域，内半径比例约 0.48，外半径比例约 1.08，并将圆周等分为 20 个角向扇区。

若某个扇区内红色像素比例不低于约 0.12，则认为该扇区获得红环支持。正式判定要求：

- 红色环带总体比例不低于约 0.30；
- 受支持扇区覆盖率不低于约 0.50；
- 最大连续缺失扇区比例不超过约 0.35。

该结构允许圆片受到一定遮挡或高光影响，但会拒绝只在局部存在红色、无法形成环状分布的候选。

### （4）白色中心与中性色约束

圆片中心为白色。系统不仅检查亮度，还联合检查 HSV 低饱和度和 Lab 中性色，以避免将浅黄色、高光绿色或有色亮斑误认为白心。当前白色候选的主要条件为：

```text
HSV 饱和度 S ≤ 60
亮度 V ≥ 190
中心区域中位饱和度 ≤ 45
Lab a、b 与中性值 128 的偏差不超过约 ±14
中性像素比例 ≥ 0.65
白色像素比例 ≥ 0.15
```

此外，算法比较中心区域和红色环带的亮度，要求白心相对环带具有足够亮度对比，当前最低对比约为 8，完全得分对应对比约为 35。

### （5）同心性与中心排红

系统检查白心候选中心与红环椭圆中心的距离。最大同心误差取 `4 px` 与红环长轴 `0.35` 倍中的较大值，以兼顾远近目标尺度。中心区域红色比例通常不得超过约 0.30；只有在红环结构非常强时才允许有限的恢复判定。该约束用于排除实心红色物体和红白结构错位的背景目标。

### （6）综合置信度与去重

圆片综合置信度主要由以下部分构成：

```text
红色环带比例          0.28
扇区覆盖质量          0.27
白心中性度            0.20
亮度对比或白色比例    0.15
椭圆长短轴比          0.10
```

若轮廓层级结构合理，可获得约 0.08 的附加奖励。正式候选最低置信度约为 0.62。重复椭圆候选根据中心距离、尺度和置信度进行合并；投影到地面后的跨视图候选在约 `0.06 m` 范围内去重。

### （7）道路区域约束的实际边界

代码保留了“圆片中心必须位于两条当前帧黄色边界形成的道路多边形内”的几何过滤功能。但该过滤只有在当前帧同时检测到左右两条边界时才生效。当前正式模式只检测左线、右线由下游走廊节点推算，因此正式左线模式中该双线多边形过滤实际上被旁路。最终报告不能声称当前圆片检测始终依赖两条实时黄线完成道路内过滤。

### （8）米制尺寸检查

算法在椭圆轮廓上采样 72 个点，经地面投影得到圆片在前向和横向的米制跨度，并使用几何平均估计直径。当前可接受视觉直径范围约为 `0.055～0.15 m`，并使用可见红环比例 `0.922076` 进行经验修正。

视觉直径主要用于候选验证、标定检查和诊断，不直接决定导航碰撞半径。正式导航中圆片物理半径固定为：

\[
r_{disc}=0.05\text{ m}
\]

因此，远近视角造成的视觉直径波动不会直接改变 costmap 或 TEB 中的障碍尺寸。

### （9）多帧跟踪与确认

检测结果转换为地面坐标后，在 BEV 空间进行目标跟踪。当前轨迹关联距离上限约为 `0.30 m`，位置平滑系数约为 0.45，连续检测 3 帧后才标记为 confirmed；允许短暂丢失 4 帧，普通视觉跟踪超时约为 0.8 s。

只有 confirmed 圆片才允许进入正式世界模型。该机制避免单帧红色噪声、局部反光或轮廓抖动直接写入导航代价地图。

### （2）内参与外参的区别

内参描述焦距、主点和镜头畸变，主要由镜头、成像器件和分辨率决定。外参和地面 Homography 描述相机相对车体及地面的安装姿态。相机支架被按压或维修后，即使分辨率和镜头未变，内参仍可能有效，但图像到地面的投影关系会发生变化。

2026-08-09 相机维修后，旧地面标定将实际 `0.500 m` 的两圆片中心距计算为约 `0.382 m`，表明外参已明显失效。重新拟合得到相机姿态相对旧模型变化约 `10.19°`。该角度来自约束拟合，只能表述为外参模型的姿态变化估计，不应写成由精密量角器直接测得的机械角度。

### （3）米制鸟瞰变换

当前 BEV 采用四点单应变换。输入图像先去畸变，再由 `cv2.getPerspectiveTransform` 建立图像地面四边形到矩形鸟瞰图的映射。当前源点按近左、近右、远右、远左排列：

```text
(-8.5684, 350.7482)
(761.4995, 339.4536)
(432.6844, 239.5077)
(210.0740, 240.4545)
```

部分源点位于图像边界外，是单应模型对地面视场边缘的几何外推，并不表示相机读取了图像外像素。

鸟瞰图尺寸为 `640 × 800 px`，对应地面宽度约 `1.019897 m`、长度约 `1.568985 m`。因此横向和前向尺度分别为：

\[
s_y\approx0.00159608\text{ m/px}
\]

\[
s_x\approx0.00196369\text{ m/px}
\]

若鸟瞰图像素为 \((u,v)\)，图像宽高为 \(W,H\)，则局部地面坐标近似为：

\[
x_{local}=(H-1-v)s_x
\]

\[
y_{left}=(W/2-u)s_y
\]

其中 x 轴沿车体前向，y 轴向左。再加上鸟瞰局部原点相对 `base_link` 的前向偏移 `0.5463 m`，得到 base_link 坐标下的地面位置：

\[
x_{base}=x_{local}+0.5463
\]

## 2.3.2.7 视觉结果进入 odom 世界模型

### （1）时间同步坐标转换

视觉检测首先得到圆片在当前 `base_link` 地面坐标中的位置。车辆在图像采集和处理期间可能已经移动，因此不能使用处理完成时刻的最新 TF 转换旧图像结果。系统使用原始图像或视觉消息时间戳查询对应时刻的：

```text
odom ← base_link
```

变换，再将圆片位置固定到 odom 坐标。若该时间戳缺少有效 TF，圆片桥接节点会丢弃本次检测，而不是退化为最新 TF，以避免运动过程中产生系统性位置偏差。

### （2）圆片冻结机制

视觉侧连续 3 帧确认后，圆片进入桥接节点的正式记忆。桥接节点在确认前使用约 0.25 的平滑系数抑制抖动；确认并满足正式任务条件后，`freeze_confirmed_position=true` 使其 odom 坐标不再随后续观测抖动。

本赛段黄线和圆片均为静态物体，机器人只需通过一次，因此冻结后的两枚正式圆片不会因以下情况自动删除：

- 相机看不到圆片；
- 圆片离开视场；
- 输入数据超时；
- 机器人已经驶过圆片；
- 视觉节点进入 LOCKED。

新一轮比赛必须通过 `/yellow_track_disc_costmap_bridge/reset_scene` 或正式场景重置流程清空圆片记忆、走廊锁存和视觉 LOCKED 状态。

### （3）虚拟 LaserScan 与 costmap

圆片桥接节点以圆片中心和固定半径 `0.05 m` 计算激光射线与圆的交点，生成虚拟 `sensor_msgs/LaserScan`，以约 10 Hz 发布到：

```text
/yellow_track_avoidance/disc_scan
```

局部和全局 costmap 将其作为障碍观测源，写入两枚圆片的占用区域。走廊节点则根据冻结的左右黄色边界，以约 5 Hz 发布：

```text
/yellow_track_avoidance/corridor_cloud
```

走廊点云作为只标记的边界障碍写入两层 costmap，使 GlobalPlanner 的路径不能穿越黄色边界。

### （4）紧凑语义障碍

GlobalPlanner 继续使用完整栅格 costmap。TEB 优化阶段不直接读取上千个 costmap 占用栅格点，而接收 4 个具有真实语义的紧凑障碍：

```text
LineObstacle：左黄线内边缘
LineObstacle：右黄线内边缘
CircularObstacle：圆片1，r = 0.05 m
CircularObstacle：圆片2，r = 0.05 m
```

正式配置中 `include_costmap_obstacles=false`，避免 TEB 将每个占用栅格视为独立点障碍。costmap 负责全局禁行表达和栅格层碰撞信息，紧凑障碍负责向 TEB 提供计算量更小、几何意义更明确的优化输入。

## 2.3.2.8 ACQUIRE—LOCKED 视觉计算优化

### （1）设计原因

初始完整视觉流水线在 N95 四核平台上约占用 2.8 个 CPU 核心，而 TEB 同时需要进行局部轨迹优化。比赛中的两条黄色边界和两枚圆片均为静态对象，一旦其世界坐标已被可靠写入下游，继续以高频率重复识别不会增加导航信息，反而会与规划线程争夺 CPU。

因此系统设计了只包含两个状态的比赛专用感知资源调度：

```text
ACQUIRE → LOCKED
```

### （2）ACQUIRE 状态

ACQUIRE 阶段完整执行：

```text
图像接收
→ cv_bridge
→ 去畸变
→ ROI
→ 黄色连续置信度
→ 法向截面与动态规划
→ 黄线拟合
→ 红色候选与椭圆拟合
→ 红环20扇区
→ 白心与同心性
→ 地面投影
→ 跟踪确认
→ ROS状态输出
```

### （3）LOCKED 进入条件

视觉节点不能只因当前帧检测到两枚圆片就停止。进入 LOCKED 前，以下状态必须在同一场景 generation 中连续稳定约 `0.5 s`：

1. competition corridor 已锁定；
2. corridor cloud 已可独立发布；
3. 圆片冻结功能已启用；
4. bridge 中恰有两枚 confirmed 正式圆片；
5. 两个目标具有唯一 ID；
6. 两枚圆片 odom 坐标均有限、合法；
7. `confirmed_positions_frozen=true`；
8. `costmap_disc_count=2`；
9. `costmap_writes_enabled=true`；
10. 固定坐标变换可用。

### （4）LOCKED 状态

进入 LOCKED 后，图像回调在格式检查和 `cv_bridge` 之前直接返回，因此不再执行去畸变、黄线检测、圆片检测、BEV、跟踪和调试图绘制。相机驱动和视觉 ROS 节点仍然存活，避免破坏 launch 中的节点依赖。

LOCKED 是单次任务锁存状态，不会因黄线离开视野、圆片丢失、话题短暂不新鲜或规划器失败自动解锁。只有显式场景 reset 才能重新进入 ACQUIRE。

| 单帧总耗时 p95 | 90.49 ms |
| 单帧最大耗时 | 103.59 ms |
| 视觉 CPU 均值 | 283.4% |
| 视觉 CPU p95 | 294.9% |
| 视觉 CPU 最大值 | 301.0% |
| RSS | 约154～160 MiB |

## 2.3.2.9 实验结果与性能分析

### （1）圆片专项 520 帧验收

历史两线识别版本在固定专项场景中共采集 520 帧，其中包含圆片的正样本 184 帧、无圆片负样本 336 帧。

正样本结果：

```text
两枚圆片同时检出       183 / 184 帧
帧级召回率             99.46%
最长连续漏检           1 帧
左圆片中心标准差       0.60 px / 0.32 px
右圆片中心标准差       0.41 px / 0.20 px
最大帧间跳变           3.77 px / 1.62 px
中位置信度             约0.973
处理耗时P50/P95        87.6 / 98.1 ms
ROS处理频率            约10.05 Hz
```

负样本结果：

```text
无圆片帧               336
误检帧                 0
```

该实验是在固定相机、固定场景和特定光照下完成的专项验收，且使用的是当时的双黄线检测条件。结果能够证明算法在该测试集中的稳定性，但不能直接扩展为所有官方随机布局和所有光照条件下的普适召回率。

### （2）当前最终 ACQUIRE 连续帧测试

当前维修后标定和左线模式下，300 帧 ACQUIRE 测试中：

- 300 帧全部完成处理；
- 左黄线 300/300 检出；
- 每帧均维持 2 个 raw 和 2 个 confirmed 圆片；
- 左黄线质量均值约 0.9096，最低约 0.9036；
- 单帧处理耗时均值约 76.45 ms，p95 约 90.49 ms；
- 两条圆片轨迹的平均 base 坐标约为 `(1.0299, 0.2683) m` 和 `(0.5650, -0.1172) m`。

最终 40 帧快速外参验证中，左黄线质量均值约 0.8649，两枚圆片 40/40 检出，表明外参调整后黄线和圆片识别仍能连续工作。

### （3）实车导航结果的写作边界

当前实车试验已经观察到 GlobalPlanner + compact-obstacle TEB 能够在部分双圆片布局中完成绕障，并存在连续多次效果良好的测试。但仓库内尚无覆盖所有官方随机布局、统一起点、统一评价标准的完整测试矩阵，因此技术报告可写“已完成多轮实车闭环验证”或列出具体试验，不宜写成“已证明全部随机布局均百分之百通过”。

视觉离线检测成功、锁止条件下的轨迹预测和实车闭环通过也应分别表述，不能将离线结果等同于实车比赛完成结果。

## 2.3.2.10 当前局限性与后续改进

1. **冻结世界模型不修正后续 x/y 漂移。** 圆片和走廊一旦固定到 odom，车辆之后若因麦轮打滑产生平移里程误差，视觉世界模型不会主动校正车辆位置。
2. **IMU不能提供绝对平移位置。** IMU主要改善 yaw 和角速度估计，无法单独消除轮式里程计的 x/y 积分误差。
3. **低频视觉地标校正尚未正式实现。** 项目已有利用冻结圆片反算车辆 x/y 的设计文档，但当前正式源码未将其作为 robot_localization 的视觉位置输入，不能在报告中写成已完成成果。
4. **当前只直接检测左黄线。** 右黄线依据固定 `0.91 m` 中心距推算，若实际道路宽度或左线标定发生变化，右侧模型会继承该误差。
5. **单边模式下道路内圆片过滤不生效。** 当前帧缺少独立右线，因此双线道路多边形的圆片中心过滤被旁路，圆片可靠性主要依赖红环、白心和多帧确认。
6. **地面投影依赖相机机械稳定。** 相机支架被碰动后必须重新标定外参或 Homography；固定内参不能自动补偿安装姿态变化。
7. **平面假设存在边界。** BEV 假设黄线和圆片位于近似平面地面，明显起伏、翘起或遮挡会影响米制投影。
8. **实验覆盖仍需规范化。** 后续应针对官方不同圆片布局、不同光照和不同起点建立统一的实车测试记录，分别统计检测、定位、碰撞和完赛结果。
9. **LOCKED 适用于静态赛场。** 若未来障碍会移动或相机在运行中可能改变安装姿态，完全停止重型视觉将不再适用，需要引入低频复核或在线定位机制。

# 七、方案演进与已废弃逻辑

以下内容可用于撰写“方案优化过程”，但不能与当前正式实现混写：

1. 早期固定 HSV 二值阈值和简单水平扫描容易受光照、透视和高光影响，已由连续颜色置信度、法向截面和动态规划替代。
2. 早期同时检测左右黄线的方案对右侧遮挡和视场完整性依赖较大，正式模式改为可靠检测左线并根据固定宽度生成右线。
3. 历史边界拟合曾使用结构张量、历史外推或延长线段，当前正式实现只保留当前观测范围内的加权直线结果。
4. 相机维修前的旧 Homography 已失效，不能继续用于当前安装姿态。
5. 40 cm gate 属于早期精度压力测试，不是正式比赛控制器。
6. 旧 passage、gate、terminal supervisor 等外围控制逻辑不是当前视觉模块的正式输出链。
7. DWA 和 SBPL 属于导航方案历史试验，不是当前视觉系统的检测算法。当前正式视觉接口服务于 GlobalPlanner + compact-obstacle TEB。
8. 实时深度图、点云和 YOLO 圆片识别没有进入当前正式视觉链。
9. 配置中仍保留旧 `yellow_scoring` 参数供历史对照，但正式启用的是 `yellow_confidence_v2`。
