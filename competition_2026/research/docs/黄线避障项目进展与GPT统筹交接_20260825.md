## 三、任务定义与硬件约束

比赛场景是：全向小车位于黄线围成的狭窄走廊内，需要绕过两枚错列红白圆片，形成 S 形横移轨迹，再到达入口/终点区域。车体规划 footprint 约为 `0.34 m × 0.33 m`，圆片物理半径按 `0.05 m` 建模。

任务的安全判定必须使用矩形车体的连续扫掠，而不是“机器人中心点没有压到圆片”。另外，导航器返回 `SUCCEEDED` 只表示软件目标满足，不能替代肉眼确认的无接触、无撞墙和正确终止。

计算平台曾出现明显实时性约束。规划控制频率为 8 Hz 时，名义周期是 125 ms；因此除 CPU 均值外，必须看 `cmd_vel` 周期 p95、不可行次数和重置长尾。

## 四、当前系统结构

### 4.1 感知与场景建模

系统没有使用深度网络完成这一部分，而是传统视觉几何链：

```text
RGB
  → 黄色连续置信度
  → 沿候选法向做截面采样与评分
  → 动态规划连接稳定黄线
  → 加权 TLS 直线拟合
  → 由可靠单侧黄线和已知道路宽度恢复走廊

RGB
  → 红色环带候选
  → 白心中性特征与分区验证
  → 连通域、尺寸、形状和布局筛选
  → 两枚圆片像素中心

黄线/圆片
  → 标定单应性
  → 米制 BEV
  → 车体坐标
  → 冻结到 odom/costmap
```

由单侧可靠黄线恢复另一侧走廊，是因为历史试验中双黄线同时检测的稳定性不如单侧主线，尤其右侧易受遮挡、裁切和场景变化影响。

### 4.2 任务态感知

系统采用 `ACQUIRE → LOCKED`：

- `ACQUIRE` 阶段以高频重型视觉获取黄线和两枚圆片；
- 场景稳定后，将几何冻结到固定坐标系；
- `LOCKED` 后保留轻量发布和必要监测，不再对每一帧重复完整视觉计算。

300 帧获取试验中，黄线质量均值/最小值为 `0.9096/0.9036`，单帧处理时间均值/p95/最大值为 `76.45/90.49/103.59 ms`。锁定后视觉 CPU 均值为 `8.87%`，相对获取阶段的 `283.4%` 下降约 `96.9%`。

### 4.3 障碍的双层表达

全局规划与局部规划不再强制使用同一种障碍表达：

- GlobalPlanner/SBPL 的 costmap 保留完整黄线栅格、圆片面积和激光数据；
- TEB 不直接吸收上千 costmap 点，只接收 `2 个 LineObstacle + 2 个 CircularObstacle`；
- 对圆片做全局拓扑决策时，可在 costmap 中封闭较窄的一侧通道；
- 对 SBPL 候选，则关闭通道封闭，让格点规划器自己选侧。

这是当前最重要的系统级改进：安全信息没有从全局地图删掉，只减少局部优化器的冗余变量。

### 4.4 雷达入口和终点

任务起点累计多帧雷达并拟合墙体几何，再由稳定的墙体关系生成入口或终点目标。设计动机是：墙端点和正前方局部反射可能稀疏或暂时漏检，不能把任务终点绑定到一次扫描中的单点。当前实现已经发展为稳健直线拟合、聚类和多点统计；汇报中应写“由多点墙体几何推算终点”，不要误写成只使用一个雷达点。

## 五、算法演进与证据

### 5.1 DWA：为什么淘汰

最初链路为 `GlobalPlanner + DWA`。在典型左错列圆片场景中，GlobalPlanner 能给出正确 S 形全局路线，但 DWA 实车约前进 0.2 m 后进入近零速度的正反振荡，22.71 s 后报告 `Robot is oscillating`。该轮初始最大横移速度约 `0.0218 m/s`，最大纵向速度约 `0.0827 m/s`。

早期 DWA 参数每周期包含约 `12 × 14 × 16 = 2688` 组速度采样，并用 1.5 s 前向模拟。15 Hz 时单周期只有 66.7 ms，实际计算常见 80～170 ms；降到 8 Hz 可显著减少循环超时，但仍不能消除狭窄 S 形路线中的局部振荡。因此结论是：实时性是问题之一，但不是唯一根因，DWA 的局部采样执行形态不适合作为当前主线。

证据类型：实车。

### 5.2 原始 TEB：运动形态改善，但暴露安全和计算问题

只替换局部规划器为 TEB 后，TEB 能生成 17～18 个姿态、约 4 s/0.88 m 的未来轨迹，并连续输出 `vx + vy`，说明它比 DWA 更适合全向 S 形横移。

但对完整矩形 footprint 做 5 mm 连续扫掠时，早期轨迹对近圆片出现约 `-28.1 mm` 净空。扩大障碍关联范围、将 `min_obstacle_dist` 设为 0.02 m、提高障碍权重并检查更多轨迹姿态后，曾产生 `+56.9～+60.2 mm` 的正净空轨迹，但也存在不可行轨迹和周期性重置。

当 TEB 直接接收 costmap 中 1078 个点障碍时：

| 指标 | 结果 |
|---|---:|
| TEB feedback 障碍数 | 1078 |
| `move_base` CPU | 70.88% |
| RSS | 65.34 MiB |
| `cmd_vel` 周期均值 | 158.39 ms |
| `cmd_vel` 周期 p95 | 491.05 ms |
| 不可行/重置 | 5 |

在感知进入 LOCKED、视觉 CPU 已显著下降后，这些数据基本不变，说明当时主要瓶颈已经转移到 TEB 的点障碍表示和轨迹优化，而不是视觉线程。

证据类型：锁车回放/锁定场景，不是实车闭环成功。

### 5.3 紧凑语义 TEB：主要工程性能改进

唯一核心变更是让 TEB 不再直接读 costmap 障碍，改接 2 条黄线和 2 个圆片；全局 costmap、footprint 和安全栅格仍保留。

| 指标 | 1078 点障碍 | 4 个紧凑障碍重复轮 | 变化 |
|---|---:|---:|---:|
| `move_base` CPU | 70.88% | 15.40% | 下降约 78.3% |
| RSS | 65.34 MiB | 56.81 MiB | 下降 8.53 MiB |
| `cmd_vel` 周期均值 | 158.39 ms | 120.20 ms | 改善 38.19 ms |
| `cmd_vel` 周期 p95 | 491.05 ms | 134.03 ms | 改善 357.02 ms |
| 周期 >187.5 ms | 6 | 0 | 消除所测长尾 |
| 不可行/重置 | 5 | 0 | 重复轮中消除 |

这证明紧凑障碍显著改善了计算和控制时序。不过重复轮连续扫掠净空仍可能为负，说明 TEB 内置 feasibility 是碰撞抽样检查，`min_obstacle_dist` 也是软代价，不能单独当作 20 mm 硬净空保证。

证据类型：严格 A/B 的锁定回放。

### 5.4 单侧通道封闭 + GP+TEB：已验证回退基线

对于每枚圆片，根据黄线与圆片形成的左右通道宽度，封闭较窄一侧，使 GlobalPlanner 确定通过较宽一侧。该规则解决“绕左还是绕右”的拓扑选择，TEB 只负责连续平滑执行。

2026-08-12 的 Stage 1/Stage 2 连续完整实车记录为：

| 轮次 | Stage 1 总时长/导航时长 | Stage 2 总时长/导航时长 | 结果 |
|---|---:|---:|---|
| A | 51.69/31.59 s | 41.94/29.89 s | 两阶段均 `SUCCEEDED` |
| B | 53.58/33.00 s | 43.90/31.49 s | 两阶段均 `SUCCEEDED` |

因此，`GlobalPlanner + compact TEB + 单侧 passage closure` 是一条有连续完整实车证据的回退基线。

证据类型：实车连续完整运行。

### 5.5 SBPL：静态能力成立，闭环稳定性未胜出

SBPL 候选使用 1 cm 地图、16 个离散航向、176 个全向运动基元、矩形 footprint 和完整圆片占用云，不使用单侧通道封闭。

正式固化的静态候选结果：

| 指标 | 结果 |
|---|---:|
| 从启动到路径就绪 | 14.84 s |
| 路径位姿数 | 792 |
| 路径长度 | 2.672 m |
| 第一/第二圆片最小净空 | +28.2/+77.4 mm |
| `move_base` 稳定 RSS | 121 MB |

它证明 SBPL 能利用 `x/y/yaw` 和全向运动基元，在不人工封侧时自主形成正净空 S 路线。更早的 5 mm 格点精确目标搜索曾失败并出现 481～623 MiB 的高内存。

后续 2026-08-13 聊天记录中，SBPL 曾有实车成功轮，也有接近起点或末端持续 `Solution not found` 的失败轮；这些结果尚未像 8 月 12 日基线那样整理成统一试验报告。因此当前只能下结论：SBPL 是有价值的对照算法，但没有稳定优于回退基线。

证据类型：静态结果已固化；后续实车为会话记录，需补 rosbag/统一统计后才能用于正式对比。

### 5.6 后期直接路径跟随器：当前集成链与历史基线发生分叉

当前比赛总入口 `/home/mowen/bit_ws/src/nav_demo/launch/815final.launch` 调用 `stage1_direct_test.launch`。其中 `competition_stage1_auto.launch` 仍负责感知、场景建模和路径准备，但 `enable_motion=false`，注释明确要求原 `move_base/TEB` 与底盘物理断开；真正发布比赛底盘命令的是 `stage1_direct_path_follower.py`。

当前 wrapper 默认值还包括：普通段最大线速度 `0.324 m/s`、末端最大线速度 `0.42 m/s`、最大角速度 `0.18 rad/s`、圆片最低诊断净空 `0.005 m`，且 `stop_on_disc_clearance_violation=false`。也就是说，当前的 5 mm 净空是告警/记录阈值，并不是会触发停车的硬安全门；后续统筹时必须把这一点单独审计。

所以必须同时保留两个“当前真相”：

1. 2026-08-12 的 GP+compact TEB+单侧封闭，是已验证的规划器回退基线；
2. 后期比赛集成入口采用直接路径跟随器，不能把它的比赛效果归因于 TEB。

后续统筹首先要决定：研究论文/汇报的主算法以哪条链为主，另一条作为何种对照；工程上不要静默互相覆盖。

## 六、早期实车失败给出的关键教训

1. **软件成功不等于物理成功**：曾有一轮 `Goal reached`，但实车擦到左侧圆片且终点物理位置错误。
2. **无接触不等于末端正确**：另一轮两枚圆片均未碰，但在末端出现高频反向旋转并靠近墙体；终点附近 8.15 s 内有 66 条命令，其中 42 条达到较高角速度。
3. **TEB 节点净空不等于连续扫掠净空**：相邻姿态较稀时，矩形车体在两姿态之间仍可能碰撞。
4. **全局有路不等于局部可执行**：DWA 失败场景中 GlobalPlanner 已有正确 S 路线。
5. **减少感知 CPU 不一定解决规划抖动**：LOCKED 后视觉 CPU 降低，TEB 的 1078 点障碍问题仍存在。

这些失败应当保留在正式汇报中，因为它们直接解释了后来的每一项改进。

## 七、感知与标定结果

### 7.1 圆片检测

专项 520 帧中：

- 有圆片正样本 184 帧，183 帧同时检出两枚圆片；
- 无圆片负样本 336 帧，误检 0 帧。

这组结果只能代表当时的固定专项场景，不能直接外推到所有光照、遮挡和相机安装状态。

### 7.2 米制 BEV

对真实 500.000 mm 圆心距的 60 帧验证，视觉均值为 501.828 mm，标准差 1.010 mm。另一次 100 帧正式记录的均值为 500.588 mm、标准差 0.968 mm，100% 落在 ±5 mm 内；Codex 聊天记录中的一次快速重标定 40 帧结果为 498.970 mm、标准差 0.302 mm，后者若进入正式报告还需关联其原始结果文件。

但相机被移动后，旧外参曾把 500 mm 测成约 381～384 mm。这说明标定数据本身可以很好，机械安装变化仍会让模型立刻失效。2026-08-18 至 19 日重新采集棋盘格并恢复相机姿态后，目标姿态角差约 0.0922°，最终比赛配置只更新了 BEV 的 8 个源点。

因此迁移验收必须包含“当前机械安装状态下的尺度复测”，不能只展示历史标定报告。

## 八、软件影子仿真与 sim-to-real

### 8.1 已有仿真是什么

工程中已有 `competition_stage1_shadow_auto.launch` 和理想里程计积分节点。它复用真实/冻结的感知、地图、全局规划和局部控制，将规划命令积分为虚拟 odom，不连接底盘。

它不是 Gazebo 全物理仿真，不包含轮胎、碰撞接触、传感器反射和支架振动，应称为“软件影子仿真”或“理想运动学闭环”。

### 8.2 它解决了什么

影子仿真可用于快速区分两类问题：

```text
同一冻结场景，影子仿真也在同一点失败
  → 优先检查路径拓扑、障碍几何、TEB 参数和终点约束

影子仿真稳定通过，实车失败
  → 优先检查 BEV/外参、里程计漂移、底盘横移响应、控制时延和物理碰撞余量
```

聊天记录中的影子试验曾显示：同步单侧通道封闭后，不可行次数明显下降，多次完成；目标安全余量调整后也出现连续零不可行轮次。但场景复现仍有波动，所以这些观察更适合指导假设，尚不足以替代标准化统计。

### 8.3 已经遇到的迁移问题

| 问题 | 表现 | 当前处理 |
|---|---|---|
| 相机机械位姿变化 | 500 mm 被测成约 381～384 mm | 重做棋盘格/BEV 外参并恢复安装姿态 |
| 单侧黄线比双线稳定 | 右线遮挡或裁切导致走廊波动 | 用可靠左线和道路先验恢复另一侧 |
| 雷达墙端点稀疏 | 单点终点可能漏检或跳变 | 多帧累计、墙体拟合、聚类/中值推算 |
| 里程计与底盘不理想 | 软件到点但物理终点或姿态不对 | 实车记录物理终点，限制速度/角速度并校准 |
| 连续碰撞未被离散检查发现 | TEB 报可行但车体扫掠负净空 | 增加 5 mm 连续矩形扫掠审计 |
| 实时性长尾 | 控制命令间隔 p95 高、顿挫/重置 | 感知锁存、紧凑障碍、8 Hz 控制和分层表达 |

## 九、建议统一的评价指标

不要只按“能不能跑通”比较算法。建议每个布局、每种算法至少记录以下数据：

| 维度 | 主指标 | 解释 |
|---|---|---|
| 成功性 | 物理无接触通过率、正确停车率、导航状态 | 物理结果优先于软件状态 |
| 安全性 | 圆片/黄线连续扫掠最小净空、最近实测距离 | 最小值越大越安全，但需同 footprint 和同布局 |
| 效率 | 总时间、导航时间、路径长度 | 只有满足安全门槛后才比较速度 |
| 平滑性 | 最大/均方角速度、横向速度变化、航向跳变 | 解释振荡、末端急转和底盘可执行性 |
| 实时性 | CPU、RSS、控制周期 mean/p95/max | p95/max 用于发现顿挫长尾 |
| 稳定性 | `Solution not found`、infeasible、reset、oscillation 次数 | 同时报告发生位置和持续时间 |
| 泛化 | 左错列、右错列、中间、边界扰动、光照扰动成功率 | 至少覆盖镜像和尺寸误差 |
| 迁移 | 影子仿真与实车成功一致率、轨迹/终点误差 | 定量描述 sim-to-real gap |

建议先确定硬门槛，例如：任何物理接触直接判失败；连续扫掠净空必须为正并预留标定/控制误差；控制周期门槛必须与实际控制频率一致。具体净空数值应根据最新相机、里程计和底盘误差分布计算，不应凭经验固定。

## 十、强化学习的建议定位

老师希望继续做强化学习，但当前不建议直接用端到端策略替换已验证链路。更稳妥的研究顺序是：

1. 冻结传统视觉、坐标系、footprint 和碰撞审计；
2. 保留 GP+compact TEB+单侧封闭作为安全回退；
3. 先让强化学习学习低维、可解释的子问题，例如：
   - 根据两侧通道宽度和定位不确定度选择绕行侧；
   - 在安全边界内调整路径横向偏置、速度上限或 TEB 权重；
   - 对几何路径跟随器输出受限的速度残差；
4. 所有学习动作经过硬安全层：footprint 连续扫掠、速度/加速度限制、越界停车；
5. 在离线日志和影子仿真中训练/筛选，再进行低速、单布局、人工急停条件下的实车验证；
6. 与 DWA、GP+TEB、SBPL+TEB 和直接路径跟随器按同一批冻结场景做 A/B。

如果目标是论文创新，优先考虑“带不确定度和安全屏障的残差策略/参数策略”，因为现有系统已经提供了稳定的几何感知、传统规划基线和可量化失败指标。端到端从图像直接输出速度会同时改变感知和控制，难以利用已有成果，也很难解释 sim-to-real 失败来自哪里。
